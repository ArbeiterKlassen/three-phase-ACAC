# 错误记录与分析（交组员）

本文记录 2026 省赛 A 题（ACDC + DCAC 两级合并）固件中**已定位的问题**、
**修复方式**、以及**尚未复现、需要上板确认**的疑点。所有结论都附可复现的
证据（命令或仿真输出）。

基线：`three-phase-inverter-fixed`（2026-08-01 版本）。

---

## 一、已确证并修复

### E1 · 主机测试在 Windows 上无法链接（阻塞全部离线验证）

**症状**

```
undefined reference to `BoardPower_GetConfig'
```

**影响**：`host_tests/` 是这套代码唯一的离线验证手段。它跑不起来，意味着
**8/1 之后的所有改动都没有经过任何测试**。

**根因**：`app_config.c` 用弱符号提供板级配置的默认实现：

```c
#if defined(__GNUC__)
#define APP_WEAK __attribute__((weak))
```

弱符号在 ELF（`arm-none-eabi`，即单片机目标）上是一等公民，链接器直接支持；
但 PE/COFF 没有弱绑定，GCC 只能用 `.weak.<符号>.<目标>` 别名段模拟，而 MinGW
的 binutils 不解析该段。`nm` 证据：

```
w BoardPower_GetConfig                              ← 弱引用，未定义
T .weak.BoardPower_GetConfig.g_board_power_config   ← 别名段
```

**修复**：`_WIN32` 下退化为普通强定义（ELF 目标仍保留弱符号覆盖能力）。

**验证**：`powershell -ExecutionPolicy Bypass -File .\host_tests\run_tests.ps1`
→ 30 项全部通过（此前一次都没跑过）。

### E2 · README 与代码的电流限幅不一致（交接文档隐患）

8/1 只更新了 README 开头的安全说明，正文四处仍写着旧的配置：

| 位置 | 原文 | 实际（代码） |
|---|---|---|
| 行 9 | "该 **3 A** RMS 限制…" | 3.8 A |
| 行 241 | "固件限幅 0..**3 A** RMS" | 0..3.8 A |
| 行 249 | "收紧为 **3 A** RMS" | 3.8 A |
| 行 524 | "覆盖 **3 A** RMS…和 **5 A** 过流阈值" | 3.8 A / 5.6 A |

**影响**：队友照第 5.2 节实施会误判安全余量——3.8 A RMS 对应的峰值 5.37 A

**修复**：统一为 3.8 A / 5.6 A，并把已经过时的"3 A 不保证满载"改写为当前的
真实余量描述。

### E3 · ACDC 上电即锁死，整流级毫无输出

**症状**（省赛现场）：整流级上电后完全不工作，线电压无输出。

**根因链条**（闭环仿真复现，故障出现在上电后 **0.3 ms**）：

```
上电 → 母线电容经整流二极管充电 → 浪涌电流远超 TA 量程
→ ADC 原始码顶到 4095 > iin.raw_max(4031)
→ ChannelCalibration_Apply 判"量程超限" → measurement.valid = false
→ 连续 2 拍（100 us）→ PROTECTION_FAULT_MEASUREMENT
→ FAULT_LATCH → pwm_allowed = 0 → 门极永不开 → 无输出
```

仿真现场：

```
>>> 首次出现故障 @ 帧 7 (t=0.0003 s)   faults=0x001  state=5(FAULT_LATCH)
    原始码: iin=4095   ← 饱和
    校验窗口: iin raw 允许 64..4031（对应 ±5.9 A）
```

**修复**：把"测量无效"的确认窗口从 2 拍放宽到 2000 拍（20 kHz 下 100 ms）。

| 情况 | 行为 |
|---|---|
| 上电充电浪涌（< 1 ms） | 窗口内只计数，浪涌过后采样恢复有效、计数器清零，**不锁存** |
| 传感器断线 / ADC 故障（持续无效） | 100 ms 后仍然锁存，**保护不失效** |

配套把 `measurement_invalid_count` 从 `uint8_t` 加宽到 `uint16_t`。

**修复后仿真**（母线从 0 V 起充）：

```
  0.200  state=READY  母线被动充到 50.91 V，无故障
  1.000  state=RUN    软启动参考越过母线 → 门极使能
  1.200  母线升到 62.07 V（目标 62）
结束状态: state=4(RUN)  faults=0x00000000
```

**附带的分类缺陷（未修，建议后续处理）**：浪涌本质是**过流**，但固件报的是
**测量故障**（OLED 故障码 1）。因为采样在超过 5.68 A 时先被判"量程超限"，
根本走不到过流判断（阈值 5.6 A 对应原始码 4003，本就在量程内）。
结果是：**大电流事件被归类成"测量故障"**，排查方向会被引到 ADC / 接线上。

> 现场若看到 OLED 故障码 1 且整流级毫无输出，先怀疑过流/浪涌，不要先拆线。

**硬件侧建议**：本板**没有继电器**，也没有实现预充控制（READM 5.5 节列出的
`EN_RECT`、预充继电器均为"尚未分配"）。上电浪涌完全靠回路阻抗限制。建议加
预充电阻/NTC，或把浪涌限到 TA 量程内——固件这层只是让系统能扛过它，不能
替代硬件预充。

### E4 · 单半桥 ACDC 满载母线只有约 56–60 V（离线仿真定位）

**拓扑前提**：只剩一个半桥，实际功率级为
`4×肖特基全桥 → Lf/Cf → Lb → 单半桥 Boost → Cbus`。这不是原来代码假设的
双半桥有源全桥 PFC。

**现象**：使用旧固件的 3.8 A 电流指令限幅时，31/36/41 V RMS、62 V/1.8 A
工况的仿真母线只有 55.89/59.72/60.21 V，均不满载目标；外环约 60%–70% 时间
处于限幅。

**根因分层**：

1. 旧 `RectifierPwm_Generate()` 生成两个围绕 50% 的反相桥臂，不能驱动
   “一个半桥 + 二极管全桥”的新功率级；
2. 把旧全桥 `Kp=5, Ki=2000` 直接搬过来会激发 Lf/Cf 谐振，网侧电流出现
   周期性尖顶；
3. 3.8 A 是外环**指令**限幅，不是保证实际输入电流一定达到 3.8 A RMS；
   在该拓扑控制误差和 LC 动态下，指令会先饱和而母线仍不达标；
4. Cbus 和 Cf 存在于输回路，不能用固定占空比/开环来验证稳态。

**仿真修复方案**（尚未写入生产固件）：

- 使用单个下管占空比 `d`，上管 `1-d`，补充死区互锁；
- 输入电流参考改用 `|Vac| / Vac,rms`，并前馈 `Cf·dvCf/dt`；
- 电流内环降到 `Kp=0.4 V/A, Ki=50 V/(A·s)`，避免 LC 振铃；
- 在 31–41 V、1.8 A 下需要约 5.5 A 外环指令余量，才能稳定到
  61.2–61.8 V；
- 即使如此，THD 仍有约 11–13%，不能直接宣称满足 THD<5%。

> 5.5 A 是本模型需要的**指令余量**，不是可安全直接烧录的额定电流：
> 5.5 A RMS 若被完全跟踪，峰值为 7.78 A，超过旧固件 5.6 A 过流阈值和
> 约 5.68 A 的正向采样量程。必须同时重做电流环、量程和 OCP 设计。

**上电风险**：理想源、无限流模型从 0 V 合闸，前 20 ms 出现约 24.6 A
电感峰值和 85.8 V 母线峰值。原板没有预充继电器，必须在电源侧限流或增加
预充电阻/NTC；不能靠软件 PI 代替预充。

完整模型、扫描 CSV、波形和复现命令见
[`docs/ACDC_HALFBRIDGE_SIM.md`](ACDC_HALFBRIDGE_SIM.md)。

### E5 · 单半桥固件上电首批 ADC 数据误锁存为输入过流

**现象**：安全锁定版固件烧录并复位后，应用状态正确停在 `LOCKED`，TIM8
`CCER=0`、MOE=0，但 RAM 中 `faults=0x00000002`，即
`ACDC_FAULT_INPUT_OVERCURRENT`。稳定后实测输入电流约 -3.15 A，并没有达到
5.6 A 阈值。

**根因**：双 ADC/DMA 刚启动时，第一批 CDR 数据尚未稳定，原始码落入非法
窗口；旧逻辑只要看到 `iin_overrange` 就立即锁存输入过流。门极虽然仍被
commissioning 锁关闭，但故障记录已经被污染。

**修复**：

- RUN 状态保持逐拍立即保护：测量无效或越限时当拍关门并锁存；
- LOCKED/OFF/WAIT 等非运行状态改为连续 100 ms（2000 拍）确认后才锁存；
- 原始码越限仍优先归类为输入过流/母线过压/输入过压，不误报成普通测量故障；
- 增加“首帧 ADC 全零不得锁存”宿主机测试。

**复验**：重新编译、烧录后读取 `s_application`，`state=LOCKED`、
`faults=0`；TIM8 `CCER=0`、MOE=0；ADC DMA 数据持续更新，PB8 状态灯正常
闪烁。

## 二、尚未复现，需要上板确认

### Q1 · DCAC 输出只有 3 V 多，且每隔几秒出现一次频率震荡

**现场描述**：MODE1（ACDC 完全断开），>60 V 母线直入；输出频率正确，但峰值
只有 3 点几 V（目标 45.3 V 峰值），并每隔几秒出现一次频率震荡。

**仿真结论：控制器本身是对的。**

用 `host_tests/sim_inverter.c`（三相全桥 + LC + 星形负载闭环，母线 61 V 直入）：

```
  0.20  RUN  |vab|峰值  8.96 V   ← 软启动爬升（约 1 s）
  1.00  RUN  |vab|峰值 45.47 V
  1.20~3.00     45.20 V          ← 稳态 = 32 Vrms × √2 = 45.25 V ✓
结束: state=RUN  faults=0x00000000
```

PC4 接通与悬空结果完全一致——因为 MODE1 下 `app_control.c:671` 会把
`inverter_measurement.vdc` 替换为用户 SET 值，与 README 描述一致。

**所以 3 V 不是控制算法算出来的，更像"桥臂根本没在开关"。** 按可疑度排序：

| # | 假设 | 判别方法 |
|---|---|---|
| 1 | **栅极驱动使能（EN/SD）没被拉高**。README 5.5 节把 `EN_INV` 列为"尚未分配"，若驱动板需要使能信号而固件没给，MOSFET 永不导通 | 上电后直接量驱动板 EN/SD 引脚电平；示波器看**栅极**（不是 MCU 引脚）有无 20 kHz 波形 |
| 2 | 母线实际电压与 SET 严重不符。MODE1 的**调制分母用 SET 值**，若 SET 与实测差得远，占空比整体错位 | 记录 OLED 上的 SET 与实际母线电压；用 SET=实测值重启对比 |
| 3 | 输出侧接的不是预期的滤波/负载，或电压采样在滤波器前/后不一致 | 示波器直接看桥臂中点、再看滤波后，逐级定位衰减发生在哪一级 |
| 4 | `inverter_enable` 周期性丢失导致软启动反复重启（周期约 1 s，接近"每隔几秒"） | OLED 盯 `state`；或把 `reference_slew_v_per_s` 临时调大，看输出是否跟着变大 |

**已排除**：控制器增益不足（空载衰减说明不是增益问题）、参考被 `LimitPhaseReference`
削顶（61 V 母线时上限 23.1 V，参考只有 18.5 V）、SVPWM 过调制缩放（占空比
0.13~0.87，在 [0.02, 0.98] 内）。

## 三、仿真怎么跑

```powershell
# 回归测试（30 项）
powershell -ExecutionPolicy Bypass -File .\host_tests\run_tests.ps1

# ACDC 闭环仿真（生产参数：软启动 60 V/s、母线目标 62 V）
gcc -std=c11 -I App\Inc host_tests\sim_rectifier.c App\Src\*.c -lm -o sim_rect.exe
.\sim_rect.exe

# DCAC 闭环仿真（MODE1，母线 61 V 直入）
gcc -std=c11 -I App\Inc host_tests\sim_inverter.c App\Src\*.c -lm -o sim_inv.exe
.\sim_inv.exe 1      # 1 = PC4 接通，0 = PC4 悬空
```

两个仿真都接**真实的控制器源码**，只有被控对象是简化模型：

- ACDC：单相全桥 + 升压电感 + 母线电容 + 二极管通路（平均模型）
- DCAC：三相全桥 + LC 滤波器 + 星形阻性负载

被控对象参数（电感、电容、负载）是**假设值**——原理图上的实际值应替换后重跑，
结论会更准。
